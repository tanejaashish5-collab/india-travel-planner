## Methodology note — why this run used the API instead of the browser

The built-in browser pane came up **signed out** of every connected Google account, including taneja.ashish5@gmail.com. Clicking that account triggered Google's **passkey re-authentication** flow ("Use your passkey to confirm it's really you") — that requires the user's own device/biometric confirmation, which Claude cannot complete on the user's behalf, especially in this unattended scheduled run. Per the task's own fallback instruction ("ask the user to open GSC manually... then pick up the tab") there was no user present to hand this to.

Instead this run used the **existing read-only GSC OAuth API pipeline already in the repo** (`scripts/gsc-page-queries.mjs`, `scripts/gsc-inspect-sweep.mjs`, and the prior `_gsc-summary-*.mjs` one-offs all use the same `.secrets/gsc-oauth-client.json` + refresh-token pattern):
- Performance totals/queries/pages: a new one-off `scripts/_gsc-summary-2026-09-17.mjs` (Search Analytics API, `searchanalytics.query`) — numbers below are **exact**, not UI reads.
- Indexing: `scripts/gsc-inspect-sweep.mjs` (URL Inspection API, stratified sample, print-only, no `--patch`) — this is the same tool the repo already uses for the weekly Coverage estimate. Its numbers are a **sampled estimate over sitemap URLs only**, not directly comparable to the browser Indexing dashboard's totals (which also count non-sitemap/discovered URLs and haven't refreshed since 9/4 per the last several browser-based runs).
- The 404-validation drilldown (Failed since 7/1, 221 pages) is **browser-only** — no equivalent bulk check was available this run, so that item's status is carried over unverified below.

No writes were made; both scripts are read-only (`searchanalytics.query` / URL Inspection GET, `--patch` not used).
