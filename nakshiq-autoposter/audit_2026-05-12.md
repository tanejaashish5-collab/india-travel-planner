## Issues found

1. 💥 **EVENING FB publish failed (HTTP 500 from Outstand).** Both the Reel video upload **and** the image fallback returned `HTTP 500` with a Cloudflare error page. IG leg of the same run published cleanly. This looks like an Outstand-side outage on FB-only video/upload routing at ~23:34 AEST. Outstand returned a non-JSON HTML body, suggesting upstream service unavailability rather than an auth issue. Worth checking Outstand status page or retrying manually.

2. 💥 **HeyGen UGC 401 — Day 8 of recurring failure.** Same `401 UNAUTHORIZED` at `https://api.heygen.com/v3/users/me`. Credential is dead. Each day this fires consumes a workflow run slot that could have been a posting run. **Recommend disabling the UGC mode-detection branch in autoposter.py until the key is refreshed** (or commenting out the cron that routes to it), since today's 07:47 UTC cron was the only candidate to hit the Tuesday Tourist-map slot and it got eaten by UGC.

3. ❌ **Tourist-map slot missed on a Tuesday.** Today is a T/Th/Sa day and the mode-router still picked UGC over tourist-map at the 07:47 UTC cron. The mode-detection priority list needs Tuesday/Thursday/Saturday DOW awareness so tourist-map outranks UGC on those days.

4. ❌ **5 scheduled SKILL.md slots in the 14:00-20:00 UTC window did not fire:** Canva visual, Reel slot 2, Reel slot 3, YT Short slot 3, and Reel-map. No workflow cron exists in that UTC window in `autoposter.yml`. If those slots are still part of the intended cadence, the workflow needs additional cron entries (or the SKILL.md schedule should be aligned with the workflow's actual cron pattern).

5. ⚠️ **Sync-only inflation.** 2 of the 7 posting runs today were sync-only (16:53 + 20:18). These succeed and commit but don't publish — they pad the success count without contributing content. Mode-detection is too eager to fall back to sync-only.

6. ⚠️ **`post_outcomes` UTF-8 surrogate warning persists** on both YT-short runs (`Could not write post_outcomes entry: 'utf-8' codec can't encode characters in position 104-105: surrogates not allowed` and `...111-112...`). Yesterday's audit flagged the same. Telemetry rows are silently dropped. Fix is `errors='replace'` or surrogate sanitization on the write path.

7. ⚠️ **No FB recovery attempt.** When the FB evening leg fails, there's no automatic retry — the IG/FB legs are independent in `run_evening` but a one-shot retry on FB-only after a server-error class would have saved this post.
